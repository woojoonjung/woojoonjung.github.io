# 프로젝트 애셋 최적화 결과

작업일: 2026-09-15. 대상은 개별 프로젝트 페이지에서 사용하는 이미지와 영상이다. 로봇, 프로필, 연구 이미지, 로고, CV 등 프로젝트 외 애셋은 변경하지 않았다. GitHub 푸시·배포는 수행하지 않았다.

## 용량 변화

| 대상 | 최적화 전 | 최적화 후 |
|---|---:|---:|
| 프로젝트 애셋 폴더 전체 | 152.17MiB | **39.52MiB** |
| Bianca 데모 영상 | 67.88MiB | **17.04MiB** |
| Silverlining 데모 영상 | 22.64MiB | **10.36MiB** |
| 센서 실험 영상 | 5.96MiB | **1.41MiB** |

프로젝트 폴더 전체는 **74.03% 감소**했다. 최적화 후 용량에는 모바일·데스크톱 이미지 후보와 새 영상 썸네일이 모두 포함된다. `.DS_Store`는 전후 계산에서 제외했다. 이는 저장·배포하는 파일의 크기이며 첫 화면의 실제 전송량이나 로딩 시간 측정값은 아니다.

| 프로젝트 페이지의 이미지·썸네일 합계 | 전 | 후 |
|---|---:|---:|
| Bianca | 7.68MiB | 0.93MiB |
| Silverlining | 24.34MiB | 1.74MiB |
| Dr.Snap | 12.28MiB | 1.62MiB |

페이지별 수치는 HTML의 기본 `src`와 영상 `poster`가 가리키는 고유 파일의 합계다. 일반적으로 큰 이미지 후보를 기본값으로 사용하며, 실제 브라우저는 화면에 맞춰 더 작은 후보를 선택할 수 있다. 지연 로딩과 접힌 영역의 이미지 때문에 처음부터 이 파일들을 모두 받는 것도 아니다.

## 적용한 변경

- 큰 PNG **16개**에서 WebP **29개**를 생성했다. 사진은 품질 86~88, 스케치가 많은 개발 이미지는 92를 사용했다.
- Bianca 아이디어 스케치와 Dr.Snap의 `eczema` 이미지는 크기를 유지하고 **무손실 WebP**로 변환했다. 원본과 디코딩된 픽셀이 동일한지 검증했다.
- 이미 작은 원본 여정 지도, 프로젝트 대표 이미지, 아이콘 등은 유지했다. 여정 지도는 파일을 유지하면서 HTML의 가로세로 비율만 실제 파일에 맞게 바로잡았다.
- 이미지에 화면별 크기 후보와 로딩 전 공간 확보를 위한 실제 크기를 연결했다.
- 큰 영상 **3개**를 H.264, CRF 21, Slow 설정으로 변환하고 빠른 시작 구조를 적용했다. Bianca는 720p, Silverlining은 1080p를 유지하고, 작은 센서 영상은 720p로 줄였다.
- 영상의 오디오는 재압축하지 않고 복사했다. 원본과 출력의 AAC 데이터가 동일함을 확인했다. 센서 영상도 사용자가 필요하면 소리를 켤 수 있다.
- Silverlining 영상은 최초 가이드의 4~8MiB 목표보다 큰 10.36MiB를 채택했다. 화질을 보수적으로 유지해도 프로젝트 전체 목표인 60MiB 이하를 충족한다.
- Dr.Snap 화면 녹화 MP4 4개는 원래 해상도·프레임·파일 내용을 그대로 유지했다. MOV 대체 링크는 해당 MP4로 연결했다.
- 수동 데모는 썸네일을 먼저 보여주고 `preload="none"`으로 재생을 기다린다.
- 센서 영상은 화면 근처에서 소스를 연결하고 화면 안에서 재생한다. 화면 밖, 비활성 탭, 페이지 이동 시 정지한다. 동작 줄이기 설정에서는 수동 재생을 제공한다.
- JavaScript가 비활성화되어도 센서 영상을 수동으로 재생할 수 있는 대체 플레이어를 남겼다.

## 원본 보관

프로젝트 저장소의 형제 폴더인 `../personal_website_asset_originals/20260915T112328Z/`에 원본 애셋과 수정 전 프로젝트 HTML·관련 코드를 보관했다. 이 폴더는 웹사이트 저장소 밖에 있다.

백업한 **56개 파일**은 복사 직후 SHA-256 해시로 일치 여부를 확인했다. 최적화된 파일로 연결을 바꾼 뒤, 더 이상 페이지에서 사용하지 않는 PNG·원본 MP4·MOV **23개**를 배포 폴더에서 제외했다. 제외 직전 원본과 백업의 일치 여부 및 사이트의 참조 여부를 다시 확인했다.

이 작업은 Git 기록을 변경하거나 이미 커밋된 다른 파일을 정리하지 않는다. 최적화 대상으로 제외한 원본 23개는 작업 당시 모두 Git 미추적 파일이었다.

## 검증한 항목

- 생성된 WebP 전체 디코딩, 기록한 크기·해시 확인.
- 무손실 출력 2개의 픽셀 일치 확인.
- 최적화한 영상 3개 전체 디코딩 오류 없음, 오디오 데이터 일치, 빠른 시작 구조 확인.
- 원본과 결과의 대표 이미지 및 영상 장면을 나란히 비교.
- 로봇을 포함한 프로젝트 외 애셋 **10개**의 해시가 작업 전과 동일함을 확인.
- 공유 프로젝트 대표 이미지 3개와 Dr.Snap MP4 4개의 파일 내용이 작업 전과 동일함을 확인.
- 사이트 HTML의 이미지·영상·썸네일·다운로드 링크·크기 후보가 모두 존재함을 확인. 누락된 로컬 애셋 참조 0개.
- 로컬 인앱 브라우저에서 데스크톱 및 390×844 모바일 화면 확인. 프로젝트 페이지에서 가로 넘침 없음.
- 큰 영상 3개와 Dr.Snap 영상 4개의 실제 브라우저 재생 확인.
- 센서 영상은 첫 화면에서 소스 미연결·재생 대기, 화면 진입 후 로딩·재생, 화면 이탈 시 정지함을 확인.
- 수동 데모는 재생 전 `readyState=0`, 재생 후 정상 준비 상태와 재생 진행 확인.
- Dr.Snap 데모 탭 변경 시 이전 영상 정지 및 다음 영상의 수동 재생 확인.
- 사이트 내부 링크로 프로젝트 간 이동한 뒤 영상 및 지연 로딩 동작 확인.
- 독립 동작 검사에서 페이지 정리·재초기화, 동작 줄이기 설정, IntersectionObserver 미지원 처리가 통과함.
- 변경한 JavaScript 구문 검사 통과. 프로젝트 미디어 함수와 호출을 제외한 공통 JavaScript는 작업 전 백업과 동일함.

실제 휴대전화, 별도의 Safari·Chrome 앱, 공개 GitHub Pages 회선에서의 속도 및 Lighthouse 점수는 이번에 측정하지 않았다. 모바일 확인은 인앱 브라우저의 화면 크기 변경을 이용했다. 전체 Git 차이의 공백 검사에는 기존 `css/site.css`, `index.html`, `projects.html` 변경에서 발생하는 공백 경고가 있어 해당 파일을 이 작업에서 정리하지 않았다.

## 파일 기록과 다시 생성하는 방법

세부 파일명, 크기·품질 설정, SHA-256 해시와 전후 수치는 `project-asset-optimization-manifest.json`에 기록했다.

`scripts/optimize-project-assets.py`는 이 작업에 포함한 파일만 명시적으로 처리한다. Pillow의 WebP 지원이 필요하며 영상 재생성에는 libx264가 포함된 FFmpeg가 필요하다. 사용한 버전은 Pillow 및 FFmpeg 버전 기록을 manifest에서 확인할 수 있다.

이미지를 다시 만들 때는 보관한 원본을 입력으로 사용한다. 예시는 프로젝트 루트에서 실행하는 명령이다.

```sh
python3 scripts/optimize-project-assets.py \
  --source-root ../personal_website_asset_originals/20260915T112328Z \
  --mode images \
  --report /tmp/project-images-regenerated.json
```

영상은 같은 원본 경로에 `--mode videos --ffmpeg /설치된/ffmpeg/경로`를 지정한다. 영상 모드는 센서·Silverlining 썸네일도 생성한다. 재생성 도구는 HTML 연결이나 원본 삭제를 수행하지 않는다. 사용한 옵션을 바꾸면 새 결과를 다시 확인한 뒤 채택해야 한다.
